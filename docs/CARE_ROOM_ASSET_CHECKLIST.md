# Dress Lab 케어룸 — UI 시안과 에셋 제작 체크리스트

2026-11-20 · **기능 확정 전 초안**. 실제 도구/애니메이션 규칙은 추후 결정한다.

## 1. 현재 UI 시안에서 가능한 것

- 케어룸 상단의 **심볼+이름 버튼**으로 페이셜 / 헤어 / 릴랙세이션 전환(하단 방 이동 버튼과 같은 시각 언어)
- 카테고리별로 독립적인 **첫 방문(상태 개선)** 과 **재방문(외형 변경 준비 또는 자유 휴식)** 도구 세트. 단계·설명 문구는 케어룸 화면에 표시하지 않음
- 하단의 장식적 선반 위에 **도구 아이콘 3개**를 그림 형태로 배치. 각 아이콘을 한 번 누르면 시연 선택 표시만 남고, 셋을 모두 누른 뒤 다른 방에 다녀오면 해당 카테고리만 재방문 도구 세트로 전환
- 페이셜/헤어 시연 완료 시 선반 옆 **책 심볼 버튼**이 나타나며, 눌러 카탈로그 모형 팝업을 열 수 있음
- 시연 초기화는 화면 버튼 없이 개발자용 진단 API(window.__dressCarePrototype.resetPreview())에서만 지원
- 기존 캐릭터 그림, 메이크업/헤어스타일/의상, 방 이동 기능은 그대로. 케어룸의 과거 헤어 편집 패널만 화면에서 숨김(기능 코드는 삭제하지 않음)

**주의:** app/care-room.js의 진행도는 브라우저 메모리에서만 유지하는 임시 상태다. 새로고침하면 다시 처음부터 시작한다. '완료'는 UI 상태의 시연일 뿐이고, 실제 피부/모발/메이크업/헤어를 변경하거나 클라이언트 데이터를 저장하지 않는다. 카탈로그 카드는 이미지 자리표시자이며 선택 기능이 없다.

## 2. 그림 에셋 — 우선순위별

| 우선순위 | 영역 | 필요한 그림 종류 | 참고 |
|---|---|---|---|
| **P0** | 공통 | 케어 도구 아이콘/썸네일, 선택됨/비활성 상태, 완료 표시 | 상단 탭 및 도구 트레이 교체용 |
| **P0** | 공통 | 손 또는 터치 커서(잡기/문지르기/누르기), 사용 범위 가이드 | 직접 조작 방식 확정 후 제작 |
| **P0** | 페이셜 최초 | 초기 피부 상태 레이어, 관리 후 기본 피부 상태 | 기존 인형과 같은 기준점 필요 |
| **P0** | 헤어 최초 | 정돈 전 머리 레이어, 정돈 후 머리 레이어 | 기존 헤어 렌더링과 충돌 방지 |
| **P0** | 페이셜 재방문 | 현재 메이크업 레이어 및 제거 과정의 마스크/중간 단계 | 처음 상태 개선과 별도 |
| **P0** | 헤어 재방문 | 기존 스타일/세팅 레이어와 세팅을 푸는 중간 단계 | 최종 스타일은 그대로 보존한 채 케어 시작 |
| **P0** | 카탈로그 | 메이크업 룩과 헤어 룩의 정사각형 또는 세로형 썸네일 | 선택 시 실제 적용되는 레이어와 ID 연결 필요 |
| P1 | 페이셜 도구 | 클렌저, 스펀지, 수건, 팩/세럼/크림 등 | 종류는 케어 규칙 확정 후 확장 |
| P1 | 페이셜 이펙트 | 거품, 물방울, 닦인 자국, 크림 도포 전후 | 필요하면 프레임 시트/마스크로 제작 |
| P1 | 헤어 도구 | 빗/브러시, 샴푸, 트리트먼트, 드라이어 등 | 커트·염색은 선택 사항 |
| P1 | 헤어 이펙트 | 샴푸 거품, 물기, 머리카락 흔들림, 드라이 바람 | 앞머리·뒷머리 레이어 구분 검토 |
| P1 | 릴랙세이션 | 타월, 손/마사지 동작, 오일, 아로마·스팀 소품 | 메이크업·헤어를 건드리지 않는 전용 레이어 |
| P1 | 공통 연출 | 캐릭터 표정 변화, 편안함 표시, 케어 종료 애니메이션 | 게임 상태 변화와 구분 |
| P2 | 공간 | 케어 침대/세면대/조명/소품/배경 | 현재 CSS 케어룸 배경 재사용 가능. 별도 그림 필수 아님 |
| P2 | 세부 효과 | 반짝임, 연기, 미세 파티클, 유리병 빛 반사 등 | 성능 고려해 추가 |

**권장 이미지 규격**: 투명 배경 PNG 또는 WebP. 도구는 캐릭터와 분리된 파일로 저장한다. 기존 의상은 252×730(standard) 및 504×900(expanded) 캔버스를 쓰지만, **확대 케어 화면과 도구 스프라이트의 규격은 별도 설계해야 한다**. 얼굴/머리용 투명 오버레이는 인형 좌표 원점과 앵커를 먼저 정해야 어긋나지 않는다.

이미지마다 제작 시 필요한 정보:
- **파일명·고유 ID·카테고리·첫 방문/재방문 구분**
- **캔버스 가로×세로, 기준점(anchor), 인형 기준 좌표, 레이어 앞/뒤 순서**
- **동작 가능한 영역(hit area), 움직임 범위, 필요하면 지우기/도포 마스크**
- **반복 프레임 수, 애니메이션 재생 조건, 완료 상태 이미지**

## 3. 사운드 에셋

| 우선순위 | 구분 | 예시 | 트리거 |
|---|---|---|---|
| **P0** | UI | 카테고리 탭, 도구 선택, 카탈로그 열기/닫기, 완료 알림 | 버튼 조작·모드 전환 |
| P1 | 페이셜 | 물 흐름, 클렌징 거품, 스펀지/타월 문지르기, 팩 도포 | 실제 제스처·도구 사용 시 |
| P1 | 헤어 | 빗질, 샴푸, 물 헹굼, 드라이어, 헤어 세팅 | 실제 제스처·도구 사용 시 |
| P1 | 릴랙세이션 | 손/오일 마사지, 타월, 스팀, 은은한 호흡/환경음 | 동작 또는 휴식 루프 |
| P2 | 연출 | 케어 시작/종료 짧은 효과음, 테마별 앰비언스 | 상태 변환·씬 연출 |

**권장 포맷:** 모바일 웹을 고려해 짧은 SFX는 압축 OGG/MP3 등을 준비하고, 필요 시 재생 호환성을 점검한다. 모든 사운드는 무음으로도 조작 가능한 상태여야 하고, **음소거/효과음 볼륨**을 제공해야 한다. 모바일 브라우저의 자동재생 제한을 고려해 처음 사용자 제스처 이후에만 오디오를 시작한다. 효과음은 루프·동시 재생 수를 제한한다.

## 4. 나중에 필요한 기능 데이터

UI 틀 이후의 핵심은 이미지 자체보다 **도구/상태/카탈로그를 연결하는 데이터**다.

| 데이터 | 목적 |
|---|---|
| clientCareState | 손님별 첫 케어 완료 여부(페이셜·헤어·릴랙세이션 각각) |
| careSession | 방문 회차, 현재 카테고리, 실제 도구 진행도, 중단/재개 |
| appearance | 현재 메이크업·헤어스타일 및 스타일 아이템 ID 저장 |
| toolCatalog | 도구 ID, 이미지, 조작 방식, 적용 가능 부위, 효과음 |
| careTransition | 각 도구가 어떤 외형 상태를 어떻게 변경하는지 |
| styleCatalog | 메이크업·헤어의 썸네일과 적용 레이어 및 선택 조건 |

**핵심 상태 규칙**
1. 첫 케어 완료 여부는 방 전체가 아닌 **카테고리별**로 저장한다.
2. 다른 방으로 이동해도 메이크업과 헤어스타일을 변경하거나 초기화하지 않는다.
3. 재방문 케어를 **선택하고 실제 실행하기 전에는** 기존 메이크업과 헤어를 지우지 않는다.
4. 첫 방문용 상태 개선과 재방문용 외형 변경 준비는 **서로 다른 시나리오/단계/도구 설정**을 가진다.
5. 릴랙세이션은 재방문 시에도 스타일에 영향 없이 반복할 수 있다.

## 5. 다음 제작 순서 제안

1. **UI 확인:** 케어룸 상단 탭/패널 크기와 가로·세로 스마트폰 화면 확인
2. **페이셜 첫 관리** 한 세트: 기본 인형 상태 이미지, 한 종류의 도구, 처리 전후 레이어, 간단한 효과음
3. **메이크업 제거** 한 세트: 현재 메이크업을 유지한 상태에서 사용자 조작으로 제거되는 과정
4. **메이크업 카탈로그** 2~3개: 썸네일과 실제 적용 레이어 연결
5. 위 흐름의 상태 관리가 검증되면 **헤어 관리**, 이후 **릴랙세이션** 확장

프로젝트 파일 배치의 예시(현재 폴더를 생성한 것은 아님):

- assets/care/common/ — 공통 도구 아이콘·터치 연출
- assets/care/facial/initial/, assets/care/facial/repeat/
- assets/care/hair/initial/, assets/care/hair/repeat/
- assets/care/relax/
- assets/care/catalog/
- assets/care/sfx/
- data/care-tools.json, data/care-styles.json — 나중에 정의할 메타데이터

최초 구현은 **에셋·실제 도구·외모 반영 없이도** UI 전환을 시험할 수 있도록 설계했다. 나중에 임시 시연 상태를 실제 게임 상태로 교체하되 기존 index.html의 인형과 의상 편집 시스템을 유지한다.
